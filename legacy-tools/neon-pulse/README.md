# NEON PULSE · 音游

一个参考 **Phigros** 玩法的浏览器音游。**音乐全部由内置合成器实时生成**（无版权问题），
**谱面从音乐事件表派生**，所以画面和声音天然严格同步，不存在对轴问题。

纯原生 HTML/CSS/JavaScript，零依赖、零构建，双击即可玩。

```bash
cd neon-pulse
python3 -m http.server 8899

```

## 触屏

**手机 / 平板直接用手指点轨道就能玩，不需要键盘。**

| 操作 | 说明 |
|---|---|
| 点按 | 点轨道任意位置（判定线上的圆点是点按目标） |
| 长按 | 按住不放，直到长按条消失 |
| 双押 | **两根手指同时按**两个轨道 |
| 扫键 | 手指按住滑到相邻轨道会自动换道（越过半格才生效，微抖不会误触） |

适配细节：

- **判定区域**：整条轨道从屏幕高度 22% 往下都可点，上方留白防止误触
- **多点触控**：`pointerId → 轨道` 映射，双押需要两根手指同时按下
- **判定精度**：用 `PointerEvent.timeStamp`（硬件时间戳）而非事件处理时刻，
  所以触屏判定精度不吃「一帧」的亏
- **布局自适应**：竖屏手机判定线压到 70%（拇指舒适区），横屏压到 58%（留出 note 下落空间），
  平板按 62%。场地宽度、按键高度、note 尺寸、HUD 字号全部随之变化
- **只认「主指针是触摸」的设备**：触屏笔记本（主指针是鼠标）仍走桌面布局，不会被降级
- **禁用误操作**：游戏中 `touch-action: none`，屏蔽滚动、双指缩放、长按菜单；
  菜单里保持 `touch-action: manipulation` 以便正常滚动
- **安全区适配**：刘海与 home indicator 区域用 `env(safe-area-inset-*)` 避让
- **点按目标 ≥ 44px**（iOS HIG / Material 建议值），滑块、开关、按钮在触摸设备下一律加大

触摸输入的延迟一般比键盘大一些，觉得判定偏可以跑一次**延迟校准**，或把判定窗口调成**宽松**。

## 内置曲目

| 曲目 | BPM | 调式 | 风格 |
|---|---|---|---|
| Neon Drive 霓虹夜驰 | 128 | A 自然小调 | Synthwave |
| Crystal Rain 水晶雨落 | 138 | C 大调 | 明快流行 |
| Void Runner 虚空疾行 | 148 | E 弗里几亚 | Dark / DnB |

每首约 66–76 秒，结构为 `intro → verse → build → drop → break → drop2 → outro`。

### 音乐是怎么来的

`js/music.js` 里有一套小型编曲引擎：

1. **作曲** — 给定调式、和弦进行和段落结构（鼓组强度 / 贝斯 / 琶音 / 主旋律 / Pad），
   用固定种子的 PRNG 生成一整张「音符事件表」（每个事件含时间、时值、音高、力度）。
2. **合成** — 事件表交给前瞻调度器（25ms 轮询、280ms 预排），实时用 Web Audio 振荡器
   加上合成器包络发声，主总线接压缩器 + 生成式混响 + 反馈延迟。
3. **谱面** — `js/chart.js` 从同一张事件表派生 note，所以音画同步是**结构性保证**而非对齐结果。

配器：kick（正弦扫频 + 噪声 click）、snare（带通噪声 + 三角波体）、hat（高通噪声）、
bass（双失正弦 + 低通包络 + sub）、lead（三振荡器失谐 + 延迟/混响送出）、
arp（锯齿拨弦 + 声像）、pad（多锯齿慢起音）、stab（和弦重音）。

## 谱面生成

难度控制三件事：**底鼓落点、参与的乐器、密度上限**。

| | EASY | NORMAL | HARD |
|---|---|---|---|
| 底鼓 | 1、3 拍 | 1、3 拍 | 每拍 |
| 参与乐器 | 底鼓/军鼓/主旋律/琶音(稀疏) | + 踩镲(四分)/琶音(四分) | + 踩镲(八分)/琶音(八分) |
| 16 分密度 | 无 | 无 | 仅 drop 段，且带切分遮罩 |
| 双押比例 | 18% | 22% | 32% |
| 密度上限 | 5 note/s | 6 note/s | 7.8 note/s |

实测生成密度：

| | EASY | NORMAL | HARD |
|---|---|---|---|
| Neon Drive | 2.9/s | 3.3/s | 5.5/s |
| Crystal Rain | 3.0/s | 3.6/s | 6.5/s |
| Void Runner | 3.4/s | 3.8/s | 6.4/s |

**密度上限是硬保证**：网格固定在十六分音符上，靠 minGap 限不住（八分以下的间隔在网格上
根本不存在），所以额外加了一层滑动窗口 —— 任何 1 秒窗口内不超过上限，超了就丢掉窗口里
优先级最低的那个（双押整组一起删，避免拆散成单押）。

轨道分配用贪心打分：避免刚用过的轨道、优先左右手交替、鼓励适度位移；
多押则以中心为基准向外对称展开。

## 导入自己的歌

设置页 → **导入本地音频**，自动扒谱：

1. 下混单声道 → 512 采样窗的 RMS 包络 → 正向差分得到「新颖度」信号
2. **节拍检测**：归一化自相关 tempogram + 对数高斯先验（120BPM）找基线周期，
   再在该周期的 0.5×/1×/2× 三个倍频候选里，用「拍点网格信息量」
   （Σ 拍点起音强度 − λ·拍数）决胜
3. 自适应阈值找起音点，量化到十六分网格；能量持续则转成**长按**

> 残留的倍频歧义不影响可玩性：候选网格仍是真实节拍的整数倍，
> 量化后的 note 落点与真实起音一致，只是谱面密度差一倍。

支持浏览器能解码的格式（mp3 / wav / ogg / m4a 等）。导入的曲目只存在于当前标签页，
刷新后需重新导入。

## 延迟校准

设置 → **开始延迟校准** → 跟着节拍敲 20 次空格，会算出平均偏移和离散度并写入设置。

原理：以 `AudioContext.currentTime` 为基准记录每次敲击与最近一次已调度节拍的时间差。
包含了音频输出延迟，所以补偿的是你**实际感知到的**延迟。

觉得偏早/偏晚时也可以直接拖动设置里的滑块。
